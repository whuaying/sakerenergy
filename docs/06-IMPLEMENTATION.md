# 06 四周实施路线与 WBS

## 假设
2-4名具工程经验人员，有可复用 Saker Runtime。四周只交付**仿真比赛 MVP**，不包括真实设备上线认证。

|周|任务|关键依赖|出口证据|
|---|---|---|---|
|W1|仓库骨架、数据库、模拟器、场站大屏|无|一键启动与固定种子重放|
|W2|规则/EWMA/异常评分、时间窗/拓扑关联、知识库、基线|W1|离线事件评分与证据链|
|W3|持久化Agent、工单审批、人工反馈、复测与Safety Gate|W2|三类故障闭环与硬拦截|
|W4|FaultBench、A/B/C/D评测、压力/安全测试、建站P1、比赛材料|W3|验收报告、演示录像、发布清单|

## 工作包
T01 Go/Next.js/Python workspace和CI；T02 schema/数据迁移；T03 数字场站可视化；T04 设备和故障模拟；T05 检测器；T06 事件聚合；T07 知识库检索；T08 数据标注/评分；T09 Saker checkpoint/重试/事件恢复；T10 工单状态机；T11 Safety Gate/权限；T12 审计与降级；T13 FaultBench 测试集冻结；T14 实验、误差分析与置信区间；T15 P1 初步建站测算；T16 答辩与发布。

## 交付门槛
M1 场站可重复仿真；M2 时序+根因候选可评分；M3 受控检修完整闭环；M4 AC01-AC25 有运行证据及实验报告。

## 范围控制
如资源紧张先砍 P1 建站、移动端和高级预测模型，不得砍安全门、人工批准、审计、三类故障重放和基线实验。
