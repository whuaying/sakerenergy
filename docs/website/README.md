# Saker Energy 官网

版本：1.0 · 2026-10-21（北京时间）

本目录记录 Saker Energy 产品官网的内容依据、使用方式和维护方法。官网围绕“让每一座场站，运行有数”介绍充储场站智能运维方案，并提供三维场站、异常场景、工单流程、年度收益假设测算与试点需求清单。

**已实现官网不代表工业产品已经实现或通过验收。** 仓库原有产品与技术文档描述的是工业平台的实施目标；网站中的设备数据、诊断候选和流程均为浏览器内的预置演示，没有连接真实设备、诊断服务或生产工单后台。

## 页面入口

正式站点：[https://saker-energy.onrender.com/](https://saker-energy.onrender.com/)。开发环境默认使用 `http://localhost:4173`，使用相同页面路径。部署和验收信息见 [发布记录](RELEASE.md)。

| 页面 | 路径 | 用途与主要操作 |
| --- | --- | --- |
| 首页 | `/` | 了解产品价值，旋转参考场站、聚焦设备，切换三类异常，阅读处理闭环与 FAQ。 |
| 平台能力 | `/platform.html` | 从场站观察、候选诊断到人工协作，理解产品的工作方式。 |
| 应用场景 | `/solutions.html` | 查看充电模块过温、储能温差异常与供电侧共同扰动的场景说明。 |
| 技术与可靠性 | `/technology.html` | 查看架构方向、数据与证据边界、只读与人工决策原则，以及后续验证路径。 |
| 探索数字场站 | `/experience.html` | 切换正常/充电/储能/供电场景，检查趋势和候选原因，推进模拟工单并下载流程记录。 |
| 规划试点 | `/contact.html` | 调整收益假设，下载测算摘要；填写站点信息并生成、复制或下载试点需求清单。 |
| 隐私与使用说明 | `/privacy.html` | 查看页面数据处理、下载、外部链接、仿真和测算的适用边界。 |

三个异常场景可以直接打开：

- `/experience.html?scenario=charger`：充电模块过温。
- `/experience.html?scenario=battery`：储能模组温差异常。
- `/experience.html?scenario=grid`：场站供电扰动。

## 怎样体验完整流程

1. 打开“探索数字场站”，选择一个异常场景。正常基线只供观察，不创建待处理事件。
2. 拖动场站模型，或使用“立体 / 俯视 / 正面”、设备聚焦、缩放与复位按钮。模型支持自动旋转开关，并响应系统的减少动态效果偏好。
3. 查看主测点趋势、当前证据和三个候选原因。每个候选都保留支持依据与尚未确认的信息。
4. 进入下方处理流程，依次整理关联证据、候选原因和模拟检查工单。在人工阶段查看检查要求并明确勾选反馈确认。
5. 选择模拟复测结果。通过后归档；未通过则重新打开，并要求再次补充人工反馈。
6. 下载仿真记录。导出文件明确标识浏览器内模拟内容，不代表真实诊断、现场检查或后端工单。

切换场景、刷新或关闭页面会重置当前流程。下载的文件由访问者自行保管；网站不上传这些记录，也不在浏览器持久化保存表单与工单状态。

## 如何使用收益测算与需求清单

“规划试点”页面中的收益测算采用[原有 ROI 模型](../10-PILOT-ROI.md)。修改场站数、事件频率、改善比例、工时和停机成本、年度投入后，页面更新人工价值、停机价值、毛收益、净收益与 ROI。结果可以为负；年度投入为零时 ROI 显示不适用。

测算依赖输入假设，不是实测经营结果、产品报价或回报承诺。人工节约与停机改善不能重复计算同一价值。

需求表单在当前页面生成一份文本清单，支持下载与复制。生成清单不会自动发送申请，页面也不收集姓名或联系方式。讨论试点时，可将自行检查过的清单带到 Saker AI 官网的现有联系渠道。

## 快速开发

使用 Node.js 24；项目没有第三方 npm 依赖。

```sh
npm run check
npm test
npm run dev
```

`npm run check` 检查 JavaScript 语法，构建 `dist`，核对页面引用与模块导入，并防止内部文件被发布。`npm test` 运行 7 项模型与流程测试。开发服务监听默认端口 4173；修改 `web` 后会重新构建，刷新页面查看变化。

## 部署目标

计划部署为 Render Static Site `saker-energy`，从 `saker-ai/saker-energy` 的 `main` 分支构建，发布目录为 `dist`，目标地址为 `https://saker-energy.onrender.com`。构建命令为 `npm run check && npm test`。

这些是部署配置与目标，不是上线完成证明。实际服务 ID、部署 ID、提交 SHA、终态和公开访问结果应由发布负责人记录在 `RELEASE.md`。
