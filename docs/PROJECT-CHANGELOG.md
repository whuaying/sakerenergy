## 当前上传内容

本次上传的是 Saker Energy 的完整项目目录，包含：

- `web/`：零依赖静态官网与浏览器内数字场站演示。
- `backend/`：遥测模拟、事件聚合、规则/趋势检测、诊断与工单原型。
- `dashboard-next/`：Next.js 运维大屏原型，包括监控、回放、评测和工单相关页面。
- `data/fault_catalog.csv`：12 类充储场站故障分类目录。
- `docs/`：产品需求、架构、安全边界、验收矩阵、实验方案、演示脚本和发布说明。
- `scripts/`、`tests/`：静态网站构建检查与浏览器本地模型测试。

## 已实现能力

1. 官网支持充电模块过温、储能温差异常和供电扰动三类浏览器内仿真场景。
2. 仿真流程覆盖异常观察、证据关联、候选原因、人工反馈、模拟复测、失败重开和审计导出。
3. 后端原型包含固定随机种子的遥测生成、12 类故障规则、EWMA 趋势检测、拓扑/时间窗事件聚合、候选根因和只读安全门设计。
4. 工程文档明确区分模拟数据、目标指标和真实工业证据；系统不向设备发送停机、合闸、复位、解锁或充放电控制指令。

## 重要边界与待修复项

- 当前评测页仍有部分展示数字，需要改为读取机器生成的逐事件评测结果。
- A/B/C/D 评测需要冻结数据、标签、阈值、查询预算和切分，并分别输出召回率、精确率、延迟、根因排名、误报与失败案例。
- 诊断知识库返回字段需要与诊断写入逻辑统一，尤其是 `version`；故障码 `F07_cell_temperature_spread` 需要与仿真器和评测器统一。
- 工单 API 的鉴权、角色校验、严格状态转移、租户隔离和幂等性，需要在代码与运行测试中补齐后才能声称安全验收通过。
- 当前公开演示数据是仿真/合成数据，不代表真实设备接入、客户部署、实测 ROI 或工业安全认证。

## 冲刺升级主线

下一阶段聚焦“充储场站疑难异常的主动补证与可恢复检修助手”：面对告警表现相似但原因不同的案例，系统选择下一项只读证据查询，依据新证据更新候选排序；证据不足时拒答并请求人工核验；工单支持暂停、恢复、复测、失败重开且不重复建单。

升级完成的最低证据包括：

- 隐藏故障注入标签的相似告警案例组。
- 固定预算下与规则、趋势、单次诊断基线的公平对照。
- 每次查询的证据编号、查询成本、候选排序变化和人工接管记录。
- 服务中断后的断点恢复、重复请求和高风险储能子集测试。
- 与云桥杯要求对应的可运行万智 Agent、公开 URL、说明书、视频和运行验证材料。

## 运行入口

```powershell
npm run check
npm test
npm run dev
```

网站默认地址为 `http://localhost:4173`。后端完整运行需要按 `docker-compose.yml` 准备 TimescaleDB、NATS、Go/Python 服务和 Next.js 环境。
