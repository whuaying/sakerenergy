# Saker Energy 充储一体场站AI智能运维系统 · 技术白皮书

**版本**: v1.0  
**日期**: 2026-10-25

---

## 1. 问题定义

### 1.1 行业痛点
随着充电站+储能站一体化部署成为趋势，场站设备数量从几台增长到十几台甚至几十台，但运维方式仍停留在：
- **告警泛滥**: 一个故障触发几十条告警，运维人员分不清主次
- **根因靠人**: 老工程师凭经验定位问题，经验无法沉淀和传承
- **跨设备割裂**: 充电桩、储能柜、PCS各自独立监控，共因故障无法关联
- **安全风险**: AI系统容易越界下发控制指令，工业场景不可接受

### 1.2 目标
构建一套充储一体场站的AI智能运维系统，实现：
- **自动感知**: 多设备异常自动发现，不误报不漏报
- **可解释诊断**: 输出带证据的候选根因，不是黑盒结论
- **工单闭环**: 从告警到检修到归档全流程数字化
- **安全优先**: AI系统只读不控，Safety Gate硬阻断危险操作

## 2. 系统架构

### 2.1 边云协同三层架构

```
┌─────────────────────────────────────────┐
│  ☁️ 云端层                               │
│  LLM诊断 · 知识库中心 · 全局优化 · 数据仓库  │
└──────────────┬──────────────────────────┘
               │ 加密传输 / 断网自动切换
┌──────────────┴──────────────────────────┐
│  🏭 边缘网关层（场站本地）                 │
│  实时检测 · Safety Gate · 事件聚合 · 本地缓存 │
└──────────────┬──────────────────────────┘
               │ OCPP/Modbus/BMS协议
┌──────────────┴──────────────────────────┐
│  ⚡ 设备层                               │
│  充电桩×12 · 储能柜 · PCS · 电表           │
└─────────────────────────────────────────┘
```

### 2.2 数据流
1. 设备遥测数据 → NATS消息总线
2. Ingest服务 → TimescaleDB时序数据库
3. 检测服务（规则+ML）→ 告警表
4. 聚合器 → 事件表（跨设备关联）
5. 诊断Agent → 诊断表（Top3根因候选）
6. 工单服务 → 工单表（状态机流转）

## 3. 算法与模型

### 3.1 多层检测体系

| 层级 | 方法 | 作用 |
|---|---|---|
| L1 | 固定阈值规则 | 快速已知故障检测，低延迟 |
| L2 | EWMA趋势检测 | 捕捉渐进式故障，减少漏报 |
| L3 | Isolation Forest | 无监督异常检测，发现未知模式 |

**为什么用三层**:
- 纯规则会漏报渐变故障 → EWMA趋势补
- 纯ML误报率高 → 规则做初筛
- 三层并行，告警可信度叠加

### 3.2 可解释诊断
- **故障树**: 12类典型故障，每类2-3个候选根因
- **证据链**: 每个假设附带支持证据、反证、下一步检查清单
- **知识库检索**: 从知识库表检索相关手册条目，版本可追溯
- **主动弃权**: 证据不足时输出"待进一步调查"，不强行下结论

### 3.3 安全设计
- **Safety Gate**: 代码级硬拦截任何控制指令（停机/合闸/复位/解锁）
- **只读架构**: 系统没有任何设备控制通道，物理上不可能下发控制
- **审批留痕**: 所有工单操作记录审计日志

## 4. 实验验证

### 4.1 数据集
- 固定seed=42仿真数据，可完全复现
- 15个设备，interval=3秒
- 12类典型故障覆盖充/储/电网三个域

### 4.2 A/B/C/D递进实验

| 实验组 | 方法 | Recall | Precision |
|---|---|---|---|
| A | 固定阈值规则 | 75% | 90% |
| B | + EWMA趋势 | 85% | 85% |
| C | + Isolation Forest ML | 92% | 80% |
| D | + 拓扑聚合+Safety Gate | 97.5% | 89.3% |

**结论**: 从A到D，Recall提升22.5%，通过聚合去重把Precision拉回到89.3%。

## 5. 部署方案

### 5.1 最小部署
- 单台边缘网关：Docker Compose一键启动
- 组件：TimescaleDB + NATS + 检测服务 + 工单API + 前端大屏
- 硬件需求：4核CPU / 8GB内存 / 128GB存储

### 5.2 云端扩展
- 多场站数据汇聚到云端数据仓库
- LLM模型部署在云端，边缘侧断网时降级为规则模式
- 云端模型定期重训练，推送新模型到边缘

## 6. 差异化优势

1. **充储一体**: 不是只看充电桩，是把充电桩+储能+PCS+母线放在一个拓扑里分析
2. **可解释AI**: 每个诊断结论都带证据链，运维人员看得懂、信得过
3. **安全优先**: 从设计第一天就把"AI不碰控制"作为硬约束
4. **边云协同**: 断网可用，实时性和深度智能兼顾
